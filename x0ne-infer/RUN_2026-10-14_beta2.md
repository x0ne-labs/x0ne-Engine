# Run of 2026-10-14: x0ne Engine 0.2.0-beta.2, attested channel on real GCP TDX + H100

First run of the beta.2 attested channel on real hardware. One `a3-highgpu-1g`
spot VM, Confidential VM type TDX, zone us-central1-a, image built from x0ne-OS
`cvm/` (Debian trixie, NVIDIA open module 595.91.07). Engine 0.2.0-beta.2
(plus `scripts/e2e-cloud.sh` and `examples/cloud_probe.rs`, then uncommitted).
Times are UTC. The VM address and the project are withheld from this record.

## What had to change to get there (attempts 1 to 8)

| # | VM life | Refusal | Cause, and fix |
|---|---|---|---|
| 1 | 1032 s | relay: connection refused, 15 min | deduced: x0ne-infer as a non-root user cannot use configfs-tsm. Test unit runs as root |
| 2 | 189 s | `CCEL: log does not start with the TCG Spec ID Event03 header` | the header is at index 1 under TDX. Fixed on 2026-10-14 |
| 3 | 184 s | `CCEL: event 39 declares 4294967295 digests` | GCE pads the log with 0xFF. Fixed on 2026-10-14, real log vendored as a fixture |
| - | offline | the image reference's policy refused the real log | reference lacks systemd-stub's section-name events, the kernel PE in RTMR1, LoadOptions and initrd tags. Reference extended for this run (below) |
| 4 | 285 s | `nvmlInit_v2: NVML error 9` | no `/dev/nvidia*` nodes; `ExecStartPre` mknod denied by the unit's device cgroup (no `m`) |
| 5 | 256 s | infer `ExecStartPre` failed | same, with `nvidia-modprobe` |
| 6 | 256 s | `mknod: Operation not permitted` | same; moved to a separate oneshot unit without device policy |
| 7 | 255 s | `nvmlInit_v2: NVML error 999 (Unknown)` | `DeviceAllow=char-nvidia-frontend` matches nothing: `/proc/devices` lists `195 nvidia` (measured). Path-based `DeviceAllow` |
| 8 | 190 s | `GPU is not accepting client requests (ready state Some(0))` (79) | nothing sets the CC ready state. Oneshot `gpu-arm` calls `nvmlSystemSetConfComputeGpusReadyState(1)` |
| 9 | 637 s | none | this record |

NVML "Unknown Error" from a device cgroup denial is a known pattern:
[NVIDIA forum 242308](https://forums.developer.nvidia.com/t/containers-losing-access-to-gpus-failed-to-initialize-nvml/242308),
[nvidia-container-toolkit #421](https://github.com/NVIDIA/nvidia-container-toolkit/issues/421).
The CCEL Spec ID index: [Linux tpm_eventlog.h patch](https://lkml.iu.edu/hypermail/linux/kernel/2507.1/00229.html).

### Test-image deviations from the x0ne OS image of 2026-10-13

- `x0ne-infer.service`: `User=root`, `CAP_SYS_ADMIN CAP_DAC_OVERRIDE`,
  `ProtectKernelTunables=no` (configfs-tsm); `--device cpu`; path-based
  `DeviceAllow` for `/dev/nvidiactl /dev/nvidia0 /dev/nvidia-modeset /dev/nvidia-uvm /dev/nvidia-uvm-tools`.
- new `x0ne-nvidia-nodes.service` (modprobe + mknod) and `x0ne-gpu-arm.service`.
  With the nodes present, `nvidia-persistenced` started (it failed in attempts 1 to 6).
- x0ne-infer deb repacked with a `--features nvml` binary (the 0.2.0-beta.2 deb is CPU-only).
- reference: the image reference from `cvm/reference.py`, extended with sha384 of
  each section name (UTF-8 + NUL), the authenticode of `.linux`, the LoadOptions
  tag (UTF-16LE cmdline + NUL) and the "Linux initrd" tag digest read from the
  real log. Supposed, not checked: the initrd tag digest depends on the initrd.

## Credentials and trust

- gcloud ran on the operator's workstation with the operator's account. No
  minimal-scope service account was created for this run, so the x0ne OS
  client container held **no cloud credential**: it did the relay, the
  verification and the probe only.
- The local apt repo was flat and unsigned (`[trusted=yes]`). Google's repo came
  from x0ne-gcloud-repo, signed.
